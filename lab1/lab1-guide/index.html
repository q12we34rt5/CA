    第 0 站 · 出發之前

    這個作業到底要你做什麼

    解開 lab1.tar 之後你拿到的是一顆已經會跑的五級管線 RISC-V 處理器。它不是半成品：資料路徑（datapath）完整，ALU、暫存器檔、記憶體介面、iterative 乘除法器全都接好了，而且現在就能跑過十個組語測試。

    缺的只有一件事：控制單元只認得 11 道指令。riscvstall-CoreCtrl.v 裡有一張 casez 控制表，每一列對應一道指令、填 20 個控制欄位。發下來的版本只填了 11 列（lui auipc addi ori add lw sw jal bne blt csrw），其餘四十幾列都是被註解掉的空殼：

      // `RISCV_INST_MSG_XORI    :cs={};
      // `RISCV_INST_MSG_SLTI    :cs={};
      // `RISCV_INST_MSG_SLTIU   :cs={};
      // `RISCV_INST_MSG_SLLI    :cs={};
      // `RISCV_INST_MSG_SRLI    :cs={};

    第 1 站 · 出發之前

    環境、目錄與第一次 build

    這一站的目標只有一個：在還沒改任何一行程式碼的情況下，看到十個測試全部 PASSED。做到這件事，你就有了一個可靠的基準線——之後任何一次失敗都是你自己剛剛改出來的，不是環境壞掉。

    解壓縮與 LAB1_ROOT

    1. 解開並記住根目錄

      講義的所有路徑都寫成 $LAB1_ROOT/...。LAB1_ROOT 不是什麼特殊變數，就是一個你自己設的 shell 變數，指向 lab1/ 這個資料夾，好讓講義的指令可以直接複製貼上。

      % tar -xf lab1.tar
% cd lab1
% export LAB1_ROOT=$PWD
% echo $LAB1_ROOT

      export 只在這個終端機視窗有效。關掉再開一個新的，要重設一次；嫌麻煩就把 export LAB1_ROOT=...（寫絕對路徑）加進 ~/.zshrc。

    2. 確認三個工具在 PATH 裡

      三樣缺一不可：iverilog（編模擬器）、riscv32-unknown-elf-gcc（編測試）、gtkwave（看波形）。

      % iverilog -V | head -1
% riscv32-unknown-elf-gcc --version | head -1
% which gtkwave

      build/Makefile 找不到 gcc 時會由 check-riscv-tools 這個目標擋下來，印出 ERROR: cannot find RISCV_GCC 並要你設 RISCV_GCC=<path>（Makefile 第 84–88 行）。裝好但沒進 PATH 的話，也可以直接 make RISCV_GCC=/完整/路徑/riscv32-unknown-elf-gcc。

    八個子目錄各是什麼

    從 .S 到 *** PASSED ***：這條鏈由誰負責

    測試有兩條編譯路線，兩條都能用

    （甲）build/Makefile 自己編。它有 %.elf : $(topdir)/tests/riscv/%.S、%.dump : %.elf、%.vmh : %.dump 三條規則（第 90–97 行），產物直接落在 build/。所以對組語測試來說，你只要把 riscv-xxx.vmh 加進 tests 清單，再 make check-asm-riscvstall，就完成了。
    （乙）講義 4.1 節的流程。cd $LAB1_ROOT/tests && mkdir build && cd build && ../configure --host=riscv32-unknown-elf && make && ../convert，產物落在 tests/build/vmh/。這條路要額外去 tests/riscv/riscv.mk 把對應的 .S 從註解裡放出來。build/Makefile 的 VPATH 同時看 tests/build/vmh 與 ubmark/build/vmh（第 81–82 行），所以這樣做出來的 .vmh 一樣找得到。
    （丙）benchmark 只有一條路。bmarks 清單裡的 ubmark-*.vmh 在 build/Makefile 裡沒有任何建置規則，必須走 ubmark/ 的 configure → make → ../convert。細節在 第 10 站。

    常見錯誤

    ./riscvstall-sim 直接執行可能會噴 bad interpreter: .../vvp: no such file or directory。iverilog 產生的是一個帶 shebang 的腳本，shebang 寫的是 iverilog 自己被編譯安裝時設定的 vvp 絕對路徑；如果你的 iverilog 是從別台機器搬過來的（這台就是），那個路徑不存在，重新 make 也一樣。所以一律照 Makefile 的寫法，前面加上 vvp：vvp ./riscvstall-sim +exe=riscv-addi.vmh +stats=1。

    單獨跑一個測試、留下波形

    示意範例 · 在 $LAB1_ROOT/build 底下
    % make riscvstall-sim                    # 只重編模擬器
% make riscv-addi.vmh                    # 只把這一個測試做成 vmh
% vvp ./riscvstall-sim +exe=riscv-addi.vmh +stats=1 +vcd=1

*** PASSED ***
--------------------------------------------
 STATS
--------------------------------------------
 status     =          1
 num_cycles =        285
 num_inst   =        125
 ipc        = 0.438596

    幾件要知道的事：

    • .vcd 落在哪裡：Pattern.v 第 140–148 行把 +exe= 給的路徑去掉最後三個字元再接 .vcd。你在 build/ 底下寫 +exe=riscv-addi.vmh，波形就是 build/riscv-addi.vcd；寫成 +exe=../tests/build/vmh/riscv-addi.vmh，波形就落在 tests/build/vmh/。跟著 .vmh 走，不是跟著你的工作目錄走。
    • 每跑一次就蓋掉上一次。想留下「壞掉的那一版」波形來對照，跑完馬上 mv riscv-addi.vcd riscv-addi-bad.vcd。
    • -rand- 版的波形多一個後綴：riscv-addi-rand.vcd（Pattern.v 第 142 行）。
    • 整批產生波形：make check-asm-riscvstall VCD=1。預設 VCD=0（Makefile 第 124 行），所以平常跑 make check 是不會有 .vcd 的。一次產十個上百 MB 的波形沒必要，除非你在追一個跨測試的共同症狀。
    • 不想等它跑完一萬個週期：加 +max-cycles=2000，超過就直接 *** FAILED *** (timeout) 收工，波形檔也小很多。

    症狀 → 先查哪裡

    tests/riscv/riscv-macros.h · 第 68–71 行
    #define TEST_CHECK_EQ( reg_, value_ )                                   \
    li    x29, __LINE__;                                                \
    li    x1, value_;                                                   \
    bne   reg_, x1, _fail;                                              \

    __LINE__ 是 C preprocessor 的行號。TEST_RISCV_END 裡的 _pass 會把 x29 改成 1、_fail 則直接沿用 x29，兩條路最後都執行同一句 csrw 21, x29。所以 status 要嘛是 1（通過），要嘛就是失敗那一行的行號。

    常見錯誤

    Illegal instruction! 不一定出現在你剛加的指令上。測試檔裡到處都有 li、nop 這些虛擬指令，組譯器會把它們展開成 addi、lui、ori 等等；只要展開出來的某道指令你還沒填進控制表，整個測試就跑不起來。所以做 Objective 1 的順序建議照 第 5 站 的分類走：先把 register-immediate 那一批補完，後面的測試才有機會跑。

    第 3 站 · Objective 1（35%）

    Objective 1 是什麼：把控制表補滿

    Objective 1 佔 35%，是四個 Objective 裡最大的一塊，也是最不需要「設計」的一塊。它的全部內容是：在 riscvstall/riscvstall-CoreCtrl.v 的 casez ( ir_Dhl ) 裡，把 32 道還沒填的指令各補上一列，另外把對應的測試加進 build/Makefile 的 tests 變數。

    講義第 3 節開宗明義：「Since the datapath already supports all rv32im instructions, only the control unit needs changes.」 這句話要當真。你不需要改 riscvstall-CoreDpath.v、不需要改 ALU、不需要改記憶體介面。ALU 的 11 種功能、op1 mux 的 7 個輸入、subword 記憶體回應的 5 條支線、乘除法器、6 個 branch_cond_*_Xhl——全部已經接好躺在那裡，只是沒有任何一列控制表去「指名」它們。唯一的例外是分支：新的分支型別需要在控制器裡多接幾條線（下面第一張圖會標出來）。

    這份工作長什麼樣子

    一列到底有多長

    39 個位元、20 個欄位，欄位定義在 riscvstall-InstMsg.v 第 167–187 行。casez 上方第 413–414 行有一列註解當表頭，把 20 個欄名對齊印出來——填表時把游標對著那一行數欄位，比什麼都可靠。

    20 個欄位，各自在哪一級被消費

    控制表是在 D 級一次決定 20 個欄位的值，然後每一欄各自搭管線暫存器走到真正用到它的那一級。這件事對填表的影響很實際：一欄如果在某一級根本沒人讀，填什麼都不會錯（可以填 x）；反過來，你以為「不重要」的欄位如果有人讀，填 x 就會讓整條路變成 x。

    填表的方法：找最近的鄰居，抄下來，只改不一樣的欄

    這 32 列沒有一列需要你發明東西。每一道指令在 datapath 上都有一個「幾乎一模一樣」的鄰居已經填好了，差別通常只有一到三欄。方法固定成四步：

    1. 找最像的現有列

      同一族、同一種立即值、同一條資料路徑。andi 的鄰居是 ori（第 419 行），sub 的鄰居是 add（第 428 行），lbu 的鄰居是 lw（第 439 行），sh 的鄰居是 sw（第 440 行），bgeu 的鄰居是 blt（第 453 行）。整列複製貼上，先讓它跟鄰居一模一樣。

    2. 沿 datapath 走一遍，列出「哪裡不一樣」

      照 P → D → X → M → W 的順序問五個問題：下一個 PC 怎麼算？ALU 的兩個輸入各是什麼？X 級要算什麼、結果取誰？要不要動記憶體、幾個 byte？最後寫什麼、寫去哪？用中文寫下差異，先不要想欄位名稱。

    3. 把每個差異翻成一欄

      這一步才打開控制表速查，逐一把「讀的是半字」翻成 mem len = ml_h。一個差異對一欄；如果你發現某個差異翻不成任何一欄，代表第 2 步判斷錯了，回去重走。

    4. 改掉那幾欄，其餘一字不動，然後立刻測

      把測試 .vmh 加進 build/Makefile 的 tests，跑一次。

      % cd $LAB1_ROOT/build
% make check-asm-riscvstall
    一次只加一道

    把 32 列一口氣寫完再測，你會拿到十幾個同時失敗的測試，而且彼此互相汙染（測試巨集本身會用到 li、bne、addi）。一次一道、加完就測，錯了你百分之百知道是誰錯。

    建議的攻略順序

    順序不是隨便排的。越前面的類別「跟現有列的差異越小」，而且後面的類別會用到前面的成果——最明顯的是 riscv-sb.S / riscv-sh.S 裡的 TEST_ST_OP 巨集會用 and 把位址對齊，所以暫存器－暫存器的 and 沒做好，sb/sh 的測試根本跑不起來。

    為什麼所有測試都跑得起來

    tests/riscv/riscv-macros.h 裡每個測試巨集只用到 li、la、addi、lw、bne、and、nop、csrw；li 會展成 lui＋addi、la 會展成 auipc＋addi。這些除了 and 之外全部隨作業附好了——所以除了 sb/sh 之外，任何一道指令只要自己那一列填對，它的測試就能獨立通過。

    各類指令攻略

    以下六類，每一類給你四樣東西：抄哪一列、要重新考慮哪幾欄（欄位名稱，不是答案）、這一類專屬的坑、要打開哪些測試。答案請自己照第 4 站的四步法推出來，查值用附錄 A 控制表速查。

    Register-Immediate：andi xori slti sltiu slli srli srai

    範本列：ori（第 419 行）。要重新考慮的欄：邏輯與比較四道（andi xori slti sltiu）只有 alu fn 一欄；移位三道（slli srli srai）還要再考慮 op1 muxsel。

    wire [31:0] shamt_Dhl = { 27'b0, inst_shamt_Dhl };
...
wire [31:0] op1_mux_out_Dhl
  = ( op1_mux_sel_Dhl == 3'd0 ) ? rf_rdata1_Dhl
  : ( op1_mux_sel_Dhl == 3'd1 ) ? shamt_Dhl
  : ( op1_mux_sel_Dhl == 3'd2 ) ? imm_u_Dhl
  : ( op1_mux_sel_Dhl == 3'd3 ) ? imm_sb_Dhl

    比較指令別跟分支條件搞混

    slti／sltiu 的結果是寫進 rd 的 0 或 1，走的是 ALU 的 addsub 單元（addsub_fn = 2'b10 / 2'b11，riscvstall-CoreDpathAlu.v 第 28–80 行），跟 X 級那六個 branch_cond_*_Xhl 是兩套完全獨立的東西。寫回路徑照 ori 抄就對了。

    要打開的測試：riscv-andi.vmh、riscv-xori.vmh、riscv-slti.vmh、riscv-sltiu.vmh、riscv-slli.vmh、riscv-srli.vmh、riscv-srai.vmh。這七個測試用的是 TEST_IMM_* 巨集，只依賴 li、bne、addi，可以任意順序單獨測。

    Register-Register：sub sll slt sltu xor srl sra or and

    範本列：add（第 428 行）。要重新考慮的欄：op1 muxsel（來源從立即值換成 rs2）、rs2 en、alu fn。就這三欄，其餘十七欄照抄。

    這一族對 datapath 來說只有一個結構性差異：op1 mux 從立即值那一支改選 rf_rdata1_Dhl。但對控制器來說還有第二個差異，而且它不影響任何資料線——rs2 en。它唯一的讀者是 stall_hazard_Dhl（第 558–576 行）。

    riscvstall/riscvstall-CoreCtrl.v · 第 558–576 行（節錄）
    wire stall_hazard_Dhl   = inst_val_Dhl && (
                          ( rs1_en_Dhl && inst_val_Xhl && rf_wen_Xhl
                            && ( rs1_addr_Dhl == rf_waddr_Xhl )
                            && ( rf_waddr_Xhl != 5'd0 ) )

    要打開的測試：九個同名 riscv-*.vmh。先做 and：下一節 sb／sh 的 TEST_ST_OP 巨集會用 and 把位址對齊到 word 邊界再用 lw 讀回來驗證。

    Memory：lb lbu lhu sb sh

    範本列：load 抄 lw（第 439 行）或你剛做好的 lh（第 443 行）；store 抄 sw（第 440 行）。要重新考慮的欄：load 是 mem len 與 memresp muxsel（成對改，第 4 站示範過）；store 是 mem req、mem len、op1 muxsel（立即值型別不同）、rs2 en、rf wen。

    store 的立即值是 S 型

    sw 那一列用的是 bm_imm_s 而不是 bm_imm_i。S 型和 I 型在指令編碼裡的位元擺法不同（圖解課第 2 章），抄 lw 去做 sb 就會踩到；抄 sw 就不會。這也是「找最近的鄰居」為什麼重要。

    store 那兩欄填什麼都行

    memresp muxsel 與 wb muxsel 對 store 來說沒有讀者（rf wen = n，writeback mux 的輸出沒人取用）。shipped 的 sw 那一列寫的是 dmm_w, wm_mem，其實填 dmm_x, wm_x 也一樣跑。照抄 sw 最省事。

    要打開的測試：riscv-lb.vmh、riscv-lbu.vmh、riscv-lhu.vmh、riscv-sb.vmh、riscv-sh.vmh。三個 load 測試只用 TEST_LD_*（依賴 la、li、bne）；riscv-sb.S／riscv-sh.S 用 TEST_ST_OP，裡面有 and 和 lw——and 沒做好這兩個測試會以莫名其妙的方式失敗。

    Branches：beq bltu bge bgeu

    範本列：bne（第 452 行）或 blt（第 453 行）。要重新考慮的欄：br type 與 alu fn。但這一類不只是加一列——控制表填對了，分支仍然永遠不會成立，因為沒有人去比對你填的 br_sel。

    怎麼挑 alu fn？不要背，用推的。六個條件訊號都是從 ALU 的輸出反推出來的：

    riscvstall/riscvstall-CoreDpath.v · 第 262–268 行
    wire   diffSigns_Xhl         = op0_mux_out_Xhl[31] ^ op1_mux_out_Xhl[31];
assign branch_cond_eq_Xhl    = ( alu_out_Xhl == 32'd0 );
assign branch_cond_ne_Xhl    = ~branch_cond_eq_Xhl;
assign branch_cond_lt_Xhl    = diffSigns_Xhl ? op0_mux_out_Xhl[31] : alu_out_Xhl[31];
assign branch_cond_ltu_Xhl   = diffSigns_Xhl ? op1_mux_out_Xhl[31] : alu_out_Xhl[31];
assign branch_cond_ge_Xhl    = diffSigns_Xhl ? op1_mux_out_Xhl[31] : ~alu_out_Xhl[31];
assign branch_cond_geu_Xhl   = diffSigns_Xhl ? op0_mux_out_Xhl[31] : ~alu_out_Xhl[31];

    讀法：每一條的「else 分支」告訴你它需要 ALU 算出什麼。eq／ne 看的是「結果是不是 0」；lt／ltu／ge／geu 看的是「結果的第 31 位元」，也就是 op0 - op1 的正負號。反推回去：你要的 alu fn 是哪一個運算，能讓這條式子在你要的情況下成立？兩個現成的例子已經示範了兩種答案——bne 用 alu_xor、blt 用 alu_sub。剩下四道自己對號入座。圖解課第 7 章把這個推導完整走過一遍，包含「為什麼不能只看 alu_out[31]」。

    要打開的測試：riscv-beq.vmh、riscv-bltu.vmh、riscv-bge.vmh、riscv-bgeu.vmh。四個測試都用 TEST_BR2_OP_TAKEN 與 TEST_BR2_OP_NOTTAKEN 成對測，所以「分支永遠不成立」與「分支永遠成立」兩種錯都抓得到。

    jalr

    範本列：jal（第 449 行）。要重新考慮的欄：pc muxsel、op1 muxsel、rs1 en。j taken 維持 y（跟 jal 一樣在 D 級就轉向），br type 維持 br_none（它不是分支，不走 X 級那套）。

    三個測試，只有兩個需要 jalr

    riscv-jalr.S 用了 7 次 jalr；riscv-jr.S 用了 6 次 jr，而 jr rs 是 jalr x0, 0(rs) 的 pseudo-instruction，所以它也需要 jalr。riscv-j.S 只用 j（＝jal x0, offset）和 addi／li——它現在就能通過，可以先加進 tests 當暖身。

    Mul/Div：mul div divu rem remu

    範本列：沒有現成的乘除法列可抄，從 add（第 428 行）起手最省事——運算元來源跟 add 完全一樣（兩個暫存器），寫回目標也一樣。要重新考慮的欄：md fn、md en、md muxsel、ex muxsel，以及 alu fn（這一族不走 ALU）。五欄。

    md muxsel 怎麼想

    乘除法器回的是 64 位元。localparam 的註解（CoreCtrl.v 第 323–325 行）已經替你說明了：mdm_l 是 "Take lower half of 64-bit result, mul/div/divu"、mdm_u 是 "Take upper half of 64-bit result, rem/remu"。五道指令對號入座即可。Objective 2 的 mulh 家族要拿的是乘積的高 32 位元——那是第 6 站的事，現在先不管。

    要打開的測試：riscv-mul.vmh、riscv-div.vmh、riscv-divu.vmh、riscv-rem.vmh、riscv-remu.vmh。全部用 TEST_RR_OP，只依賴 li、bne。

    三條指令，兩種難度

    Objective 3：bypass 實作路線

    這一站不是「照著填格子」，是一個小型的電路設計。所以它要分成可以各自測試的里程碑：每做完一個就編譯一次、跑一次測試，確認沒有把原本會過的東西弄壞。一次改完五件事再編譯，你會拿到一堆互相糾纏的錯誤。

    做法：把「這條指令是 load」做成一個 1 bit 控制訊號，像 rf_wen_Dhl → rf_wen_Xhl 那樣管線化一級，然後用它去 gate 原本 X 那三項條件。現成的材料 CoreCtrl 裡都有：第 336 行的 localparam ld、第 520 行 cs[`RISCV_INST_MSG_MEM_REQ] 的用法、第 621–624 行那一串 X <- D 的管線化賦值。

    wire is_load_Dhl = ( cs[`RISCV_INST_MSG_MEM_REQ] == ld );
...
    is_load_Xhl <= is_load_Dhl;        // 放進既有的 X <- D always 區塊
...
wire stall_load_use_Dhl = ... is_load_Xhl ... ;   // 只看 X 級

assign stall_Dhl = ( stall_Xhl || stall_muldiv_Dhl || ... );
    muldiv 的結果在 X 級也不一定能前饋

    execute_mux_out_Xhl 在 X 級要等 muldivresp_val 才是正確值。好消息是你不用另外處理：既有的 stall_muldiv_Dhl（第 553 行）以及 X 級等待回應的 stall 已經讓 mul 在算完之前不會離開 X，D 也走不了。前提是你 M4 只拿掉 stall_hazard_Dhl，不要順手把 stall_Dhl 裡的其他項也刪掉。

    M5：怎麼知道 bypass 真的在做事

    這是最容易自我欺騙的一步：測試全過不代表 bypass 有生效。因為「一直 stall」本身就是正確行為，你即使 M4 完全沒做，所有測試（含 *_BYP 巨集）還是會 PASSED。唯一的證據是 cycle 數。

    補測的部分，riscv-macros.h 已經備好整組 *_BYP 巨集，數字參數就是「相依距離」：

    巨集測什麼
    TEST_RR_DEST_BYP( n, … )n = 0/1/2 分別打到 X／M／W 三條路徑
    TEST_RR_SRC01_BYP / SRC10_BYPrs1 和 rs2 兩顆 mux 都要獨立測到
    TEST_LD_DEST_BYP( 0, … )就是 load-use：這一條逼出 M4 的 1 拍 bubble
    TEST_BR2_SRC01_BYPbranch 的兩個來源（branch 在 X 解，但運算元仍在 D 讀）
    TEST_JALR_SRC0_BYPjalr 的 rs1 → jumpreg_targ_Dhl 那條路

    陷阱清單

    這六個佔了絕大多數的 debug 時間
    • gating 抄漏：inst_val_*、rf_wen_*、!= 5'd0 三個條件只要漏一個，就會從一個泡泡、一個不寫暫存器的指令、或 x0 前饋出垃圾。原文在 CoreCtrl 第 558–576 行，逐項對照著抄。
    • 忘了 rs1_en / rs2_en：lui、jal 這類指令的 rs1／rs2 欄位根本不是暫存器編號，但仍會湊巧等於某個 rf_waddr。少了這個 gate，一接到 jumpreg_targ 就出事，而且會造成假相依白白吃掉 IPC。
    • 忘了 jalr 的 rs1：jumpreg_targ_pretruncate_Dhl（CoreDpath 第 196 行）還接著 rf_rdata0_Dhl。
    • 從 X 級的 load 前饋：那時資料還沒從記憶體回來，你會拿到 ALU 算出來的位址。這正是 is_load_Xhl 存在的理由。
    • x0：rf_waddr == 0 的寫入必須被排除，否則 add x0, ... 之後讀 x0 會讀到非零值。
    • 只改了 rs1 忘了 rs2：兩顆 mux、兩條 select、兩組 *_byp_Dhl 訊號，全部成對出現。TEST_RR_SRC10_BYP 專門抓這個。

    riscvlong：接上管線化乘除法器

    這一站的分數最重（30%），風險也最高：它不是「加一個功能」，而是把整條管線從 5 級改成 7 級， 然後把原本會讓全機停 30 幾拍的迭代式乘除法器，換成一個固定 4 級延遲、每拍都能收新請求的管線化單元。 牽動的檔案是 riscvlong-CoreCtrl.v、riscvlong-CoreDpath.v、riscvlong-Core.v、 riscvlong-CoreDpathPipeMulDiv.v 四支。

    M1：先把管線延長，乘除法器一個字都不要改

    手冊建議的做法是：乘除法單元的第 0、1 級疊在現有的 X、M 上（免費，不增加延遲）， 第 2、3 級沒有現成的級可以疊，所以真的新增兩個管線級 X2、X3，插在 M 和 W 之間。

                     && ( ... == rf_waddr_X2hl )
                     && ( rf_waddr_X2hl != 5'd0 );

    : ( rs1_M_byp_Dhl  ) ? ...

    (1) 漏掉 csr_wen 的複製。測試靠 csrw 21, x29 回報 PASS/FAIL。X2、X3 忘了接 csr_wen / csr_addr，那筆寫入就永遠不會發生（測試 timeout），或早兩拍發生（讀到還沒算好的值）。
    (2) rf_waddr 比對用錯級。寫 rs1_X3_byp_Dhl 時整段複製貼上，裡面卻還留著 rf_waddr_X2hl。症狀是特定距離的相依才錯，非常難抓 —— 寫完後把每個 byp 訊號的級字尾逐字念一遍。
    (3) stall 鏈順序接反。正確方向是 stall_Whl(0) → stall_X3hl → stall_X2hl → stall_Mhl → stall_Xhl → stall_Dhl → stall_Fhl。 接反了會出現「前面停、後面繼續跑」，指令被複製或吃掉。

    (5) Verilog 隱含 1-bit net。打錯字的 stall_X2h1（數字 1）不會報錯，會自動變成一條 1-bit wire。 除錯時可以暫時在檔案最上面加 `default_nettype none 讓這類錯誤變成編譯錯誤， 也一定要看 iverilog -Wall 的警告輸出 —— 但記得繳交前拿掉，以免影響其他檔案。

    Benchmark 評估

    手冊第 5 節要求用 $LAB1_ROOT/ubmark 下的四支 C benchmark 評估三個處理器。 評分是 100% 看程式碼，沒有報告分數 —— 但 benchmark 是最強的正確性證據： 它們是真實的 C 程式，會用到 assembly 測試不見得涵蓋的指令組合與相依距離。 assembly 測試全過但 benchmark 掛掉，幾乎一定是你的旁路或 stall 有洞。

    先把 benchmark 編出來

    build/Makefile 的 bmarks =（第 56–60 行）列了四個 .vmh，但 build/Makefile 裡沒有編它們的規則 （assembly 測試有，benchmark 沒有）。它靠 VPATH += $(topdir)/ubmark/build/vmh（第 82 行）去找現成的檔案。 所以你必須先在 ubmark/ 自己 configure + make 一次。

    1. 在 ubmark 下建一個 build 目錄並 configure

      ubmark/ 裡有 configure、Makefile.in、 convert、以及 ubmark/ubmark/ 放四支 .c 和它們的 .dat 測資。 和 tests/ 完全一樣的 autoconf 流程。

      % cd $LAB1_ROOT/ubmark
% mkdir build
% cd build
% ../configure --host=riscv32-unknown-elf
% make
    2. 跑 convert

      它會建出 bin/ dump/ vmh/ obj/ dep/ 五個子目錄，把 ELF 搬進 bin/， 對每個執行檔跑一次 objdump，再用 scripts/objdump2vmh.py 轉成 .vmh。

      % ../convert
% ls vmh

      跑完應該看到四個檔：ubmark-vvadd.vmh、ubmark-cmplx-mult.vmh、 ubmark-masked-filter.vmh、ubmark-bin-search.vmh。

    3. 回 build 跑

      run-bmark-* 會用 BMARK_SIM_FLAGS = +verbose=1 （build/Makefile 第 127 行）執行，所以 .out 裡會有 STATS 區塊。

      % cd $LAB1_ROOT/build
% make run-bmark-riscvstall
% make run-bmark-riscvbyp
% make run-bmark-riscvlong
    benchmark 在 Objective 1 完成之前一定跑不過

    四支 C 程式會用到 slli、sub、beq、lbu 等 還沒加進控制表的指令。控制表沒有那一列 → cs 整包是 x → 訊號變 x， 你會看到滿螢幕的 RTL-ERROR ... x assertion failed : memreq0_val，最後 *** FAILED *** (timeout)。這不是 benchmark 壞掉，是 Objective 1 還沒做完。先把 check-asm 全部弄綠再來跑 benchmark。

    四支 benchmark 各操什麼

    benchmark主要運算會不會用到乘法器掛掉時先懷疑
    ubmark-vvadd向量逐元素相加，單純迴圈核心迴圈沒有乘法基本的 load / store / add / 分支、load-use
    ubmark-cmplx-mult複數乘法：每個元素 4 次乘法 + 加減大量 mulmul 的控制表列、mul-use stall、乘除法器整合
    ubmark-masked-filter5 點遮罩濾波：乘係數後除以 norm乘 + 除（out/norm 是變數除法）mul、divu、位元組載入 lbu、型別轉換
    ubmark-bin-search二分搜尋，大量比較與分支只有 /2（編譯器會轉成移位）各種分支 beq/bge/bltu、slt 家族、control hazard

    把數字填進這張表

    數字從 .out 檔尾的 STATS 區塊讀。格式和 assembly 測試一樣，例如 riscv-add-stall.out：

    *** PASSED ***
--------------------------------------------
 STATS
--------------------------------------------
 status     =          1
 num_cycles =        468
 num_inst   =        232
 ipc        = 0.495726
    常見錯誤

    只跑 make run-bmark-riscvlong 就下結論。要比較就得三個都跑，而且 在同一份 ubmark/build/vmh 上跑。中途重編 benchmark（改了 .c 或換了 gcc 版本）會讓 num_inst 變動，前後的數字就不能比了。

    打包繳交

    手冊第 6.3 節寫得很直白：「If the tarball is not created from this folder, grading will not be possible.」 —— 打包位置錯了，是零分級別的失誤，不是扣幾分。這一站只有兩件事：確認該改的檔案都在、用對的方式打包。

    該出現在 tarball 裡的東西

    清掉產生物，然後打包

    % cd $LAB1_ROOT/build
% make clean
% cd $LAB1_ROOT/tests
% rm -rf build
% cd $LAB1_ROOT/ubmark
% rm -rf build
% cd $LAB1_ROOT
% cd ..
% COPYFILE_DISABLE=1 tar --exclude .DS_Store --exclude .git -cvzf 學號-lab1.tar.gz lab1
    macOS 專屬的三個坑

    (1) .DS_Store 與 ._*。Finder 逛過的目錄都會留下 .DS_Store； macOS 內建的 tar 預設還會為每個檔案額外塞一個 ._檔名 的 AppleDouble 附檔。 解開之後助教會看到一堆 ._riscvlong-CoreCtrl.v，很醜而且可能干擾自動化腳本。 用 COPYFILE_DISABLE=1 關掉 AppleDouble，用 --exclude .DS_Store 排掉前者。
    (2) .git 目錄。你的工作目錄裡有 .git。它可能比全部原始碼加起來還大好幾倍， 而且含有你的 commit 訊息與 email。手冊只要求原始碼，建議用 --exclude .git 排掉。 （若你的 .git 在外層而不是內層 lab1/ 裡，就不會被打包進去，加這個參數也無害。）
    (3) rm -rf 打在錯的目錄。cd $LAB1_ROOT/tests 和 rm -rf build 是兩行； 如果第一行因為打錯字沒成功，第二行就會在你原本所在的目錄執行。 安全的寫法是把它們寫成一行：rm -rf $LAB1_ROOT/tests/build $LAB1_ROOT/ubmark/build， 路徑寫死，不依賴當下位置。

    像助教一樣驗收你的 tarball

    交出去之前，用一個全新的空目錄把它解開再重建一次。這會抓到所有「只有在我的機器上才會過」的問題： 忘了 commit 的檔案、被 clean 掉卻沒有重建規則的產生物、寫死的絕對路徑。

    % mkdir /tmp/check && cd /tmp/check
% tar -xzf ~/學號-lab1.tar.gz
% tar -tzf ~/學號-lab1.tar.gz | head -3      # 確認第一行是 lab1/
% cd lab1/build
% make check-asm-riscvstall
% make check-asm-riscvbyp
% make check-asm-riscvlong
