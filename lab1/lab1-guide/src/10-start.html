第 0 站 · 出發之前

這個作業到底要你做什麼

解開 lab1.tar 之後你拿到的是一顆已經會跑的五級管線 RISC-V 處理器。它不是半成品：資料路徑（datapath）完整，ALU、暫存器檔、記憶體介面、iterative 乘除法器全都接好了，而且現在就能跑過十個組語測試。

缺的只有一件事：控制單元只認得 11 道指令。riscvstall-CoreCtrl.v 裡有一張 casez 控制表，每一列對應一道指令、填 20 個控制欄位。發下來的版本只填了 11 列（lui auipc addi ori add lw sw jal bne blt csrw），其餘四十幾列都是被註解掉的空殼：

riscvstall/riscvstall-CoreCtrl.v · 第 418–424 行
      // `RISCV_INST_MSG_ANDI    :cs={};
      // `RISCV_INST_MSG_XORI    :cs={};
      // `RISCV_INST_MSG_SLTI    :cs={};
      // `RISCV_INST_MSG_SLTIU   :cs={};
      // `RISCV_INST_MSG_SLLI    :cs={};
      // `RISCV_INST_MSG_SRLI    :cs={};
      // `RISCV_INST_MSG_SRAI    :cs={};

整個作業分成四個 Objective，從「把這張表填滿」開始，一路做到「把一顆四級管線的乘除法器塞進管線」。四個 Objective 不是四份獨立作業，而是同一份程式碼被複製三次、逐次加功能——這件事決定了你該用什麼順序做，後面會專門畫一張圖講。

第 1 站 · 出發之前

環境、目錄與第一次 build

這一站的目標只有一個：在還沒改任何一行程式碼的情況下，看到十個測試全部 PASSED。做到這件事，你就有了一個可靠的基準線——之後任何一次失敗都是你自己剛剛改出來的，不是環境壞掉。

解壓縮與 LAB1_ROOT

  1. 解開並記住根目錄

    講義的所有路徑都寫成 $LAB1_ROOT/...。LAB1_ROOT 不是什麼特殊變數，就是一個你自己設的 shell 變數，指向 lab1/ 這個資料夾，好讓講義的指令可以直接複製貼上。

    % tar -xf lab1.tar
% cd lab1
% export LAB1_ROOT=$PWD
% echo $LAB1_ROOT

    export 只在這個終端機視窗有效。關掉再開一個新的，要重設一次；嫌麻煩就把 export LAB1_ROOT=...（寫絕對路徑）加進 ~/.zshrc。

  2. 確認三個工具在 PATH 裡

    三樣缺一不可：iverilog（編模擬器）、riscv32-unknown-elf-gcc（編測試）、gtkwave（看波形）。

    % iverilog -V | head -1
% riscv32-unknown-elf-gcc --version | head -1
% which gtkwave

    build/Makefile 找不到 gcc 時會由 check-riscv-tools 這個目標擋下來，印出 ERROR: cannot find RISCV_GCC 並要你設 RISCV_GCC=<path>（Makefile 第 84–88 行）。裝好但沒進 PATH 的話，也可以直接 make RISCV_GCC=/完整/路徑/riscv32-unknown-elf-gcc。

八個子目錄各是什麼

從 .S 到 *** PASSED ***：這條鏈由誰負責

測試有兩條編譯路線，兩條都能用

（甲）build/Makefile 自己編。它有 %.elf : $(topdir)/tests/riscv/%.S、%.dump : %.elf、%.vmh : %.dump 三條規則（第 90–97 行），產物直接落在 build/。所以對組語測試來說，你只要把 riscv-xxx.vmh 加進 tests 清單，再 make check-asm-riscvstall，就完成了。
（乙）講義 4.1 節的流程。cd $LAB1_ROOT/tests && mkdir build && cd build && ../configure --host=riscv32-unknown-elf && make && ../convert，產物落在 tests/build/vmh/。這條路要額外去 tests/riscv/riscv.mk 把對應的 .S 從註解裡放出來。build/Makefile 的 VPATH 同時看 tests/build/vmh 與 ubmark/build/vmh（第 81–82 行），所以這樣做出來的 .vmh 一樣找得到。
（丙）benchmark 只有一條路。bmarks 清單裡的 ubmark-*.vmh 在 build/Makefile 裡沒有任何建置規則，必須走 ubmark/ 的 configure → make → ../convert。細節在 第 10 站。

第一次跑：確切的指令與真實輸出

  1. 進 build 目錄，編出模擬器 
    % cd $LAB1_ROOT/build
% make

    第一次會跑一陣子：iverilog 要編兩個模擬器（riscvstall-sim 與 riscvstall-randdelay-sim），gcc 要編 tests 清單裡的每個測試。

  2. 跑全部組語測試（固定 1 週期記憶體） 
    % make check-asm-riscvstall

    在還沒改任何東西的原始 handout 上，你會看到九個測試通過；下面是加了講義示範的 lh 之後的實際輸出（十行）：

      [ PASSED ] riscv-add-stall.out
  [ PASSED ] riscv-addi-stall.out
  [ PASSED ] riscv-bne-stall.out
  [ PASSED ] riscv-blt-stall.out
  [ PASSED ] riscv-jal-stall.out
  [ PASSED ] riscv-lui-stall.out
  [ PASSED ] riscv-lw-stall.out
  [ PASSED ] riscv-ori-stall.out
  [ PASSED ] riscv-sw-stall.out
  [ PASSED ] riscv-lh-stall.out

    這一行行是 Makefile 第 196 行那段 perl 從每個 .out 撈出 *** ... *** 印的，順序就是 tests 清單的順序。

  3. 再跑一次隨機延遲版 
    % make check-asm-rand-riscvstall

    輸出格式一樣，檔名多一個 -rand。兩個都過才算過，理由見下一節。

  4. 看一個測試的完整輸出

    make 只印摘要；細節在 .out 檔裡。

    % cat riscv-lh-stall.out
*** PASSED ***
--------------------------------------------
 STATS
--------------------------------------------
 status     =          1
 num_cycles =        449
 num_inst   =        187
 ipc        = 0.416481
../Pattern.v:210: $finish called at 4530 (1s)

    status = 1 就是通過。ipc 現在只有 0.42——每兩三個週期才退休一道指令，因為 stall 版遇到任何 data hazard 都要停三個週期。Objective 3 的 bypass 就是要把這個數字拉上來。

常見錯誤

./riscvstall-sim 直接執行可能會噴 bad interpreter: .../vvp: no such file or directory。iverilog 產生的是一個帶 shebang 的腳本，shebang 寫的是 iverilog 自己被編譯安裝時設定的 vvp 絕對路徑；如果你的 iverilog 是從別台機器搬過來的（這台就是），那個路徑不存在，重新 make 也一樣。所以一律照 Makefile 的寫法，前面加上 vvp：vvp ./riscvstall-sim +exe=riscv-addi.vmh +stats=1。

兩個模擬器的差別

riscvstall-sim 與 riscvstall-randdelay-sim 是同一份 Verilog 編出來的，差別只在編譯時的三個 define（Makefile 第 144–160 行）：

第 2 站 · 出發之前

工作循環：改 → 編 → 測 → 除錯

接下來三十幾道指令、三個目錄，你會把同一個循環重複大約三十五次。循環越短越好：一次只加一道指令，加完馬上測。一次貼十列進控制表然後看到 FAILED，你要找的嫌疑犯就有十個。

常見錯誤

把 riscv-andi.vmh 加進去卻忘了尾端的 \，make 不會報錯，只會安靜地把清單截斷。想確認 Makefile 真的看到了你的測試，用它內建的除錯目標：make debug-tests，它會把 tests 變數的完整內容印出來（Makefile 第 276–277 行）。

單獨跑一個測試、留下波形

示意範例 · 在 $LAB1_ROOT/build 底下
% make riscvstall-sim                    # 只重編模擬器
% make riscv-addi.vmh                    # 只把這一個測試做成 vmh
% vvp ./riscvstall-sim +exe=riscv-addi.vmh +stats=1 +vcd=1
VCD info: dumpfile riscv-addi.vcd opened for output.
*** PASSED ***
--------------------------------------------
 STATS
--------------------------------------------
 status     =          1
 num_cycles =        285
 num_inst   =        125
 ipc        = 0.438596

幾件要知道的事：

  • .vcd 落在哪裡：Pattern.v 第 140–148 行把 +exe= 給的路徑去掉最後三個字元再接 .vcd。你在 build/ 底下寫 +exe=riscv-addi.vmh，波形就是 build/riscv-addi.vcd；寫成 +exe=../tests/build/vmh/riscv-addi.vmh，波形就落在 tests/build/vmh/。跟著 .vmh 走，不是跟著你的工作目錄走。
  • 每跑一次就蓋掉上一次。想留下「壞掉的那一版」波形來對照，跑完馬上 mv riscv-addi.vcd riscv-addi-bad.vcd。
  • -rand- 版的波形多一個後綴：riscv-addi-rand.vcd（Pattern.v 第 142 行）。
  • 整批產生波形：make check-asm-riscvstall VCD=1。預設 VCD=0（Makefile 第 124 行），所以平常跑 make check 是不會有 .vcd 的。一次產十個上百 MB 的波形沒必要，除非你在追一個跨測試的共同症狀。
  • 不想等它跑完一萬個週期：加 +max-cycles=2000，超過就直接 *** FAILED *** (timeout) 收工，波形檔也小很多。

症狀 → 先查哪裡

tests/riscv/riscv-macros.h · 第 68–71 行
#define TEST_CHECK_EQ( reg_, value_ )                                   \
    li    x29, __LINE__;                                                \
    li    x1, value_;                                                   \
    bne   reg_, x1, _fail;                                              \

__LINE__ 是 C preprocessor 的行號。TEST_RISCV_END 裡的 _pass 會把 x29 改成 1、_fail 則直接沿用 x29，兩條路最後都執行同一句 csrw 21, x29。所以 status 要嘛是 1（通過），要嘛就是失敗那一行的行號。

常見錯誤

Illegal instruction! 不一定出現在你剛加的指令上。測試檔裡到處都有 li、nop 這些虛擬指令，組譯器會把它們展開成 addi、lui、ori 等等；只要展開出來的某道指令你還沒填進控制表，整個測試就跑不起來。所以做 Objective 1 的順序建議照 第 5 站 的分類走：先把 register-immediate 那一批補完，後面的測試才有機會跑。

把講義的 Tips 變成習慣

講義第 8 節列了五條 Tips。翻譯成這個作業裡具體的動作：

講義的 Tip在這個作業裡具體怎麼做
Use incremental development一次一列。填完 andi 就馬上把 riscv-andi.vmh 加進 tests 跑一次，綠了才動 xori。三十二道指令 = 三十二個綠燈，不是最後一次大爆炸。
Use gtkwave to debug存一個 template.sav（build/ 已經有一個）把常看的訊號固定下來：pc_Fhl、ir_Dhl、cs、alu_fn_Xhl、stall_*、rf_wen_Whl。每次開新波形直接套用。
Take advantage of the unit testing frameworkmake check-asm-riscvstall 一次跑完整份清單，成本只有十幾秒。不要因為「只改了一列」就只跑那一個測試——回歸（regression）就是這樣被抓到的。
Sketch the hardware before coding填一列之前，先在紙上把那道指令走過 P→F→D→X→M→W：它讀幾個暫存器？operand 1 是立即值還是暫存器？ALU 做什麼？要不要發記憶體請求？寫回的是 ALU 結果還是記憶體回應？答案就是那二十欄。
Define control-datapath interactions clearly不要新增你不確定接到哪裡的控制欄位。講義明說欄位已經齊了，唯一需要新增的是分支用的 *_taken_Xhl 之類的 helper wire。
用 git 或至少用備份

handout 沒有附版本控制。在 $LAB1_ROOT 下 git init 然後每通過一道指令就 commit 一次，是這個作業投資報酬率最高的五分鐘：第 0 站那張拷貝鏈的圖說過，晚發現的 bug 要在三個目錄修三次，有 commit 歷史你至少知道是哪一次改動引進的。記得在 .gitignore 排掉 build/*.vcd 和 build/*.out，而且這個 repo 不可以 push 到公開的地方。
