第 16 章 · 模擬與測試

Testbench：不會變成電路的那一半 Verilog

Verilog 其實是兩種語言混在一起：一半描述硬體（前面 15 章），另一半是只給模擬器執行的測試程式。後者有延遲、有印字、能讀檔，行為就像一般的軟體程式——因此無法合成、也畫不出電路圖。Testbench.v、Pattern.v 和所有 *.t.v 檔都屬於這一類。

產生時脈與 reset

Pattern.v · 第 47–61 行
initial begin
  clk = 1'b0;                 // initial：模擬開始時執行一次
end

always #5 clk = ~clk;         // 每過 5 個時間單位反相一次 → 週期 10

initial begin
  reset_proc = 1'b1;
  reset_mem  = 1'b1;

  repeat ( p_reset_cycles ) @( negedge clk );   // 等 2 個下降緣

  reset_proc = 1'b0;
  reset_mem  = 1'b0;
end

Pattern.v 裡也有看起來像硬體的部分：第 160–173 行的 num_cycles、num_inst 計數器用的是標準的 always @(posedge clk) + <=，就是第 7 章的暫存器加上 + 1。它只是剛好住在 testbench 裡而已。

執行模擬時可用的參數

這些都是 Pattern.v 用 $value$plusargs 讀取的：

./riscvstall-sim +exe=riscv-add.vmh +stats=1 +vcd=1

  +exe=<檔名>        要執行的程式（必填，.vmh 格式）
  +max-cycles=<N>    超過 N 個週期就判定 timeout（預設 100000）
  +verbose=1         結束時印出 num_cycles / num_inst / ipc
  +stats=1           效果相同（會把 verbose 一併打開）
  +vcd=1             輸出波形檔 riscv-add.vcd
強烈建議

用 +vcd=1 產生波形，用 GTKWave 打開，把 state_reg、a_reg、b_reg、result_reg 拉出來看，對照第 14 章的模擬表格。看過一次真實波形，「每個上升緣所有暫存器同時更新」這件事就會變成直覺。
