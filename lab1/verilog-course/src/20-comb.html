assign 與運算子：直接長出邏輯閘

assign 的意思是「把右邊這坨電路的輸出，永久焊在左邊這條線上」。它不是「執行一次的賦值」，右邊任何輸入一變，左邊就跟著變。

運算子對照表

運算子合成出來的硬體成本
& | ^ ~逐位元的 AND / OR / XOR / NOT 閘每位元一個閘
&& || !邏輯運算，結果只有 1 位元（運算元先被壓成「是否非零」）很小
== !=比較器：逐位元 XNOR 再全部 AND 起來小
+ -加法器（進位鏈）中
<< 1、>> 1（固定量）純接線，見第 5 章零
<< alu_a[4:0]（可變量）桶式移位器 (barrel shifter)：5 層 mux，分別決定要不要移 1、2、4、8、16 位中
>>>算術右移，左邊補正負號位元。運算元必須是 signed 才有效，所以 Shifter 特地宣告 wire signed [31:0]同上
* / %整顆組合式乘法器／除法器。ALU 的 MulDiv 單元用了，面積非常大、延遲非常長很大
? :多工器，見第 4 章小
面積 vs 時間

寫 alu_a * alu_b 只要一行，但會合成出幾千個閘，而且一個時脈週期內要算完。lab1 的重點——imuldiv-IntMulIterative.v——就是改用「一個加法器 + 32 個週期」慢慢算，拿時間換面積。第 14 章會完整畫出來。

第 4 章 · 組合邏輯

? : 三元運算子：就是多工器 (MUX)

多工器是 lab1 裡出現最多次的元件：幾個輸入、一個選擇訊號、一個輸出，選擇訊號決定哪個輸入「通過」。在 Verilog 裡最直接的寫法就是 條件 ? 真的時候 : 假的時候。

riscvstall/riscvstall-CoreDpath.v · 第 114–115 行
wire [31:0] pc_mux_out_Phl_final
  = pc_redirect_pending ? pc_redirect_targ : pc_mux_out_Phl;

串接的 ? : → 多選一

riscvstall/riscvstall-CoreDpathAlu.v · 第 128–133 行
assign result
  = ( logical_fn == 2'b00 ) ?  ( alu_a & alu_b ) :
    ( logical_fn == 2'b01 ) ?  ( alu_a | alu_b ) :
    ( logical_fn == 2'b10 ) ?  ( alu_a ^ alu_b ) :
    ( logical_fn == 2'b11 ) ? ~( alu_a | alu_b ) :
                               ( 32'bx );

嚴格照字面，這段程式是四層串接的二選一 mux（有優先順序）。但因為四個條件互斥，合成工具會自動化簡成上圖的四選一。同樣的寫法在 CoreDpath.v 出現十幾次：pc_mux、op0_mux、op1_mux、wb_mux……看到這個排版就直接在腦中畫一個梯形。

第 5 章 · 組合邏輯

{ } 拼接與 {n{ }} 複製：只是重新整理電線

{a, b} 把兩束線併成更寬的一束（a 在高位）。{24{x}} 把 x 複製 24 份。兩者都不產生任何邏輯閘，純粹是接線。

riscvstall/riscvstall-CoreDpath.v · 第 315–316 行（load byte 的符號擴展）
wire [31:0] dmemresp_lb_Mhl
  = { {24{dmemresp_msg_data[7]}}, dmemresp_msg_data[7:0] };

指令解碼裡更誇張的「重新排線」也是同一招。RISC-V 的 branch 立即值在指令裡被拆成四段，riscvstall-InstMsg.v 第 290–294 行把它拼回來：

assign imm_sb = { {20{msg[31]}},   // 正負號複製 20 份
                  msg[7],          // imm[11]
                  msg[30:25],      // imm[10:5]
                  msg[11:8],       // imm[4:1]
                  1'b0 };          // 最低位固定是 0（位址一定是偶數）

原始碼用 `RISCV_INST_MSG_IMM_SIGN 這類巨集代替數字，第 11 章會解釋；這裡我先把巨集展開成數字方便閱讀。

第 6 章 · 組合邏輯

always @(*)：用 if / case 寫組合邏輯

邏輯一複雜，用 assign 加一長串 ? : 會很難讀。always @(*) 讓你改用 if、case 來描述同樣的組合邏輯。@(*) 的意思是「裡面用到的任何訊號一變，就重新計算」——這正是組合邏輯的行為。

riscvstall/riscvstall-CoreDpathAlu.v · 第 199–226 行（節錄）
reg [10:0] cs;

always @(*)
begin
  cs = 11'bx;                       // ① 預設值
  case ( fn )
    4'd0  : cs = { 2'd0, 2'b00, 2'bxx, 2'bxx, 3'bxx  }; // ADD
    4'd1  : cs = { 2'd0, 2'b01, 2'bxx, 2'bxx, 3'bxx  }; // SUB
    4'd2  : cs = { 2'd1, 2'bxx, 2'b00, 2'bxx, 3'bxx  }; // SLL
    // ...
    4'd15 : cs = { 2'd3, 2'bxx, 2'bxx, 2'bxx, 3'b100 }; // REMU
  endcase

  { out_mux_sel, fn_addsub, fn_shifter, fn_logical, fn_muldiv } = cs;  // ② 拆包
end

這種「把一整列控制訊號打包成一個向量 cs，再一次拆開」的寫法，是 lab1 的招牌風格。riscvstall-CoreCtrl.v 第 411 行開始那張巨大的指令解碼表，就是同一個模式的放大版（39 位元寬）。

組合 always 的三條規則

  1. 敏感列表寫 @(*)。
  2. 裡面用 =（blocking）賦值。（<= 留給時脈區塊，見第 8 章。）
  3. 每一條路徑都要給每個輸出一個值。最保險的做法就是像上面 ① 那樣，一進來先給預設值。

違反第 3 條會怎樣：意外的 latch

  if ( s ) y = a;                if ( clk ) q_np <= d_n;
  else     y = b;                // 沒有 else：clk = 0 時 q_np 要維持原值
陷阱

lab1 的 FSM 在 always @(*) 開頭寫 state_next = state_reg;、ALU 寫 cs = 11'bx;，都是為了避開這個問題。你自己寫的時候請養成同樣的習慣。

巢狀 if → 串接的 mux

riscv_CoreDpathAluAddSub（第 26–88 行）用多層 if / else if 實作 SLT（小於比較）。不需要另外畫圖：每一層 if 就是一顆二選一 mux，外層條件的 mux 接在比較靠近輸出的位置。條件 addsub_fn == 2'b10、diffSigns、sum[31] == 1'b0 分別成為三層 mux 的選擇訊號。
