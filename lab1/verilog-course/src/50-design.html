有限狀態機 (FSM)：正反器 + 兩塊組合邏輯

需要「分好幾個步驟做事」的硬體，都靠狀態機控制。lab1 的迭代乘法器有三個狀態：IDLE（等請求）→ CALC（算 32 輪）→ SIGN（修正正負號、等對方把結果收走）。

寫成 Verilog 時，標準做法是拆成三個區塊，各自對應一塊硬體：

imuldiv/imuldiv-IntMulIterative.v · 第 284–358 行（節錄）
// ① 狀態暫存器 —— 循序邏輯
reg [1:0] state_reg;
always @ ( posedge clk ) begin
  if ( reset ) state_reg <= STATE_IDLE;
  else         state_reg <= state_next;
end

// ② 次態邏輯 —— 組合邏輯
reg [1:0] state_next;
always @ ( * ) begin
  state_next = state_reg;                         // 預設：留在原地（也避免 latch）
  case ( state_reg )
    STATE_IDLE: if ( mulreq_go )    state_next = STATE_CALC;
    STATE_CALC: if ( is_calc_done ) state_next = STATE_SIGN;
    STATE_SIGN: if ( mulresp_go )   state_next = STATE_IDLE;
  endcase
end

// ③ 輸出邏輯 —— 組合邏輯：每個狀態該送出哪些控制訊號
always @ ( * ) begin
  case ( state_reg )
    //                 req  resp sign res  cntr     a        b        result
    //                 rdy  val  en   en   mux_sel  mux_sel  mux_sel  mux_sel
    STATE_IDLE: cs = { y,   n,   y,   y,   op_load, op_load, op_load, op_load };
    STATE_CALC: cs = { n,   n,   n,   y,   op_next, op_next, op_next, op_next };
    STATE_SIGN: cs = { n,   y,   n,   n,   op_x,    op_x,    op_x,    op_x    };
  endcase
end

③ 那張表值得細看：每一列是一個狀態，每一欄是一條控制線。用 y/n/op_load 這些 localparam 取代 0 和 1，整張表就像規格書一樣能直接閱讀。

綜合範例：迭代乘法器的 Control + Datapath

imuldiv-IntMulIterative.v 是 lab1 的核心，也用到了前面幾乎所有語法。它的頂層只做一件事：例化一個 datapath（資料怎麼流、怎麼運算）和一個 control（上一章的 FSM），再用 11 條線把兩者接起來。這種「control 指揮 datapath」的切法是數位設計最常見的架構，整顆處理器（CoreCtrl.v + CoreDpath.v）也是這樣切的。

演算法：直式乘法的二進位版

每一輪看乘數 b 的最低位：是 1 就把 a 加進結果。然後 a 左移一位（相當於直式乘法往左錯開一格）、b 右移一位（換看下一位）。32 輪之後結果就是 a × b。負數先轉成正數運算，最後再依正負號補回來。

後綴意思
_Phl _Fhl _Dhl _Xhl _Mhl _Whl這個訊號屬於哪一級管線：PC 選擇、Fetch、Decode、eXecute、Memory、Writeback。看到 pc_Xhl <= pc_Dhl 就知道這是 D→X 的管線暫存器
_p（如 d_p、wen_p）原始碼註解：「sampled on rising clk edge」——這個輸入會在上升緣被取樣
_mux_sel、_en、_fn分別是 mux 選擇線、暫存器 enable、運算單元的功能選擇——全都是 control → datapath 的控制線（圖中的藍色虛線）
_val / _rdy / _msgval/rdy 握手的三條線：有效、就緒、資料本體

讀 datapath 的建議順序：先找所有 always @(posedge clk)，把暫存器畫成一排；再看每個暫存器的輸入來自哪個 wire，往回追就是該級的組合邏輯。
