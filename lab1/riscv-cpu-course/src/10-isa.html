第 0 章 · RISC-V 指令集

ISA：軟體與硬體的合約

基礎篇的最後，你已經會把一份規格寫成 control + datapath。但處理器的「規格」是誰定的？答案是指令集架構 (ISA, Instruction Set Architecture)：一份寫死的合約，規定軟體可以叫硬體做哪些事、每件事的結果是什麼。合約以外的東西——用幾級管線、要不要 bypass、乘法器幾個週期——通通屬於微架構 (microarchitecture)，硬體設計者可以自由發揮。

這個區分是整份 lab 的骨架：lab1 裡有三個目錄 riscvstall、riscvbyp、riscvlong，它們是同一個 ISA 的三種微架構。同一個 riscv-addi.vmh 丟進去，三者必須算出一模一樣的答案，只有花的週期數不同。

程式設計師看得到的狀態

合約的第一條，是列出「程式可以觀察與修改的東西」。rv32 只有三樣：

  • PC (program counter)：32 位元，指向目前這條指令的位址。lab1 的 reset 值是 0x00080000（riscv-isa.txt 第 5 節）。
  • 32 個通用暫存器 x0–x31，每個 32 位元。其中 x0 永遠讀出 0，寫進去也沒用。
  • 記憶體：以 byte 定址 (byte-addressed)，一個位址放一個 byte；一個 word 佔 4 個 byte，採 little-endian——最低位址放最低的那個 byte。

x0 恆為零：硬體長什麼樣

「x0 永遠是 0」聽起來像個約定，其實是兩顆實體電路撐起來的：讀的時候一顆 mux 把 0 塞回去，寫的時候一個條件把寫入擋掉。

riscvstall/riscvstall-CoreDpathRegfile.v · 第 20–32 行
  // We use an array of 32 bit register for the regfile itself
  reg [31:0] registers[31:0];

  // Combinational read ports
  assign rdata0 = ( raddr0 == 0 ) ? 32'b0 : registers[raddr0];
  assign rdata1 = ( raddr1 == 0 ) ? 32'b0 : registers[raddr1];

  // Write port is active only when wen is asserted
  always @( posedge clk )
  begin
    if ( wen_p && (waddr_p != 5'b0) )
      registers[waddr_p] <= wdata_p;
  end

load／store 架構

翻一遍上面的清單你會發現：只有 lb/lh/lw/lbu/lhu 和 sb/sh/sw 會碰到記憶體，沒有任何一條算術指令能直接對記憶體做加法。這叫 load/store 架構 (load–store architecture)。對硬體設計者來說這是天大的好消息：記憶體存取只會出現在管線的固定一站，不必在每個運算單元旁邊都接一條記憶體匯流排。

指令格式：32 個 bit 怎麼切

第 2 章 · RISC-V 指令集

立即數：被打散的常數

第一次讀 SB 型的圖，幾乎每個人都會問同一句話：為什麼立即數要被切成四塊，而且順序還是亂的？

答案是：這些欄位不是為了好看給人讀的，是為了讓連線最短。RISC-V 的設計者先把 rs1／rs2／rd／funct3 的位置釘死（第 1 章那張對齊圖），剩下的洞才拿來塞立即數。於是立即數被迫讓路。作為補償，他們讓每一種立即數都遵守兩條規則：

  • 符號位元永遠是 inst[31]。所以符號延伸 (sign extension) 的那條線可以最早開始拉，不必等解碼完才知道要複製哪一位。
  • 同一個立即數位元盡量待在同一個指令位元。例如 imm[10:5] 在 I、S、SB、UJ 四種格式裡都來自 inst[30:25]——所以那 6 條線可以直接接死，不需要 mux。

這五種立即數在 lab1 裡是同時算出來的，全部寫在一個模組裡，之後由 op1_mux 選要用哪一個（第 6 章）：

這五行全部是 assign + 串接 {}，沒有任何運算子——也就是說，這裡完全沒有邏輯閘，只有接線（基礎篇第 5 章）。{21{x}} 是複製語法，代表把同一條線接到 21 個地方。下面三張圖把這些接線畫出來。

shamt = inst[24:20]

移位指令 slli/srli/srai 的移位量不需要 12 個 bit——32 位元的值最多移 31 位，5 個 bit 就夠。所以它直接借用 I 型立即數的最低 5 位，也就是 `define RISCV_INST_MSG_SHAMT 24:20（第 70 行），跟 rs2 的位置完全重疊。datapath 的 op1 mux 有一個專門的 bm_shamt 輸入就是為了它。

U 型立即數與「造一個 32 位元常數」

I 型立即數只有 12 位，能表示 −2048 到 +2047。要把任意 32 位元常數放進暫存器，就得靠 lui（load upper immediate）：它把 20 位立即數放到高 20 位，低 12 位補 0。

於是組譯器用 lui + addi 兩條指令造出任意常數，這個組合有個代號叫 li（load immediate）。但這裡有一個很容易踩到的陷阱：addi 的立即數是有號的。

第 3 章 · RISC-V 指令集

指令巡禮與 pseudo-instruction

這一章把 lab1 會用到的每一族指令走一遍。目標不是背下來，而是建立一種「看到指令就知道它要動用哪些硬體」的直覺——因為 Objective 1 要你填的控制表，每一列正是在回答這個問題。

暫存器–立即數 與 暫存器–暫存器

這兩族是同一件事的兩個版本：第二個運算元從哪裡來。

常見錯誤

sltiu 的立即數還是先做有號延伸，只有「比較」那一步是無號的。所以 sltiu rd, rs1, -1 等於「rs1 是不是小於 0xffffffff」，答案幾乎永遠是 1。riscv-isa.txt 第 4.3 節寫得很清楚：R[rd] = ( R[rs1] <u sext(imm) )。

移位有兩種右移，差別只在「左邊補什麼」：

lui 與 auipc

lui rd, imm 把 imm_u 直接寫進 rd（等於「0 + imm_u」）；auipc rd, imm 則是 PC + imm_u，用來組出「相對於目前位置」的位址（la pseudo-instruction 就靠它）。兩者都是 U 型，兩者都不讀暫存器。

載入與儲存

位址一律是 R[rs1] + sext(imm)——所以 load/store 也要用 ALU 做一次加法。差別在於取幾個 byte、以及不足 32 位時怎麼補。

指令取幾 byte不足 32 位時指令寫幾 byte
lb1符號延伸sb1（rs2 的最低 byte）
lbu1零延伸sh2
lh2符號延伸sw4
lhu2零延伸位址需對齊：lh/sh 偶數、lw/sw 4 的倍數
lw4不必延伸

分支：六種條件，兩種比較

六條分支指令 beq bne blt bge bltu bgeu 都是 SB 型，目標都是 PC + imm_sb。b*u 結尾的用無號比較，其餘用有號比較。同樣 32 個 bit，兩種比較給出完全相反的答案：

跳躍：jal 與 jalr

兩條都會做兩件事：把 PC+4 存進 rd（叫「link」），然後改 PC。jal 的目標是 PC + imm_uj（UJ 型，PC 相對）；jalr 的目標是 (R[rs1] + imm_i) & 0xfffffffe（I 型，暫存器相對，最低位強制清 0）。有了這兩條就能做函式呼叫與返回。

M extension：64 位元乘積的上下半

mul rd, rs1, rs2 把兩個 32 位元相乘，但結果其實有 64 位元——mul 只取低 32 位，高 32 位要靠 mulh 系列取得。這就是 Objective 2 的內容。

csrw：測試用的出口

csrw 是這個實作裡唯一的 CSR（control/status register）指令，編碼是 I 型的變形：funct3 = 001、opcode = 1110011、而且 rd 必須是 00000（InstMsg.v 第 143 行）。立即數欄位放的不是常數而是 CSR 編號。這次只用到編號 21（0x015）的 status：寫進去就等於告訴模擬器「測試結束了」，值 1 代表通過，其他值代表失敗的行號。測試巨集最後一段就是這樣寫的：

tests/riscv/riscv-macros.h · 第 32–38 行
#define TEST_RISCV_END                                                  \
_pass:                                                                  \
    addi   x29, x0, 1;                                                  \
                                                                        \
_fail:                                                                  \
    li     x2,  1;                                                      \
    csrw   21, x29;                                                     \
1:  bne    x0, x2, 1b;                                                  \

順著讀一遍就懂了：測試走完沒出事就落到 _pass，把 1 放進 x29；中途失敗則直接跳到 _fail，此時 x29 裡是 TEST_CHECK_EQ 先前寫入的 __LINE__。兩條路都會執行 csrw 21, x29，然後停在一個無窮迴圈 bne x0, x2, 1b。怎麼看這個回報值，見第 20 章。

Pseudo-instruction：組譯器的語法糖

測試檔裡出現的 nop、li、mv、j、jr、ret 都不是真的指令，硬體裡沒有它們的 opcode。它們由組譯器展開成上面那些真指令——這也是為什麼 InstMsg.v 第 124 行特別警告：不要在控制模組裡實作 NOP。

mv rd, rs1addi rd, rs1, 0加 0 就是搬值
li rd, imm（小）addi rd, x0, immimm 在 −2048～2047 時一條就夠
li rd, imm（大）lui rd, hi; addi rd, rd, lohi 在 lo 為負時要 +1（第 2 章）

為什麼要在意這件事

你在 make check-asm-riscvstall 看到 riscv-j.vmh 或 riscv-jr.vmh 失敗時，要去控制表裡找的是 JAL 和 JALR 這兩列，不是「J」和「JR」。同理，nop 之所以能動，是因為你已經實作了 addi。

想一想

sw 為什麼要用 S 型而不是 I 型？

看答案

因為 sw rs2, imm(rs1) 需要兩個來源暫存器（位址基底 rs1、要寫的資料 rs2），卻不需要目的暫存器 rd。I 型只有一個來源欄位，而 rd 的那 5 個 bit 對 store 完全沒用——所以 S 型就把立即數拆成兩半，低 5 位借用 rd 的位置，同時保住 rs1、rs2 在原位。這正是第 1 章那張對齊圖的用意。
