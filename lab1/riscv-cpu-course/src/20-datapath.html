第 4 章 · 一條指令的旅程

把一道指令切成五段：F / D / X / M / W

前三章我們把指令當成一個 32 位元的數字在看。從這一章開始，它要真的跑起來：走進 lab1 這顆處理器，一級一級往前推。

為什麼要切？如果一道指令從頭到尾（讀記憶體取指令、讀暫存器、算、存記憶體、寫回暫存器）都在同一個時脈週期裡做完，那個週期就得長到塞得下整條路徑，時脈頻率會很難看。管線 (pipeline) 的作法是把這條長路徑切成五段，中間插入暫存器，每段只做一件事：週期變短，而且五道指令可以同時在不同段裡前進。這就像自助洗衣：洗、烘、摺、收各用一台機器，你不會等第一批衣服摺完才開始洗第二批。

lab1 的五級是 Fetch、Decode、eXecute、Memory、Writeback。訊號名字一律以 _Fhl、_Dhl、_Xhl、_Mhl、_Whl 結尾，看到後綴就知道這條線活在哪一級（hl 表示它在時脈邊緣之後的那個週期有效）。

第六級：那個沒有名字的 P

翻開 riscvstall-CoreDpath.v，你會先看到一堆 _Phl。這不是打錯字，而是 F 前面還有一小段「PC 邏輯」。原因是記憶體是有延遲的：送出位址之後，資料要下一個週期才回來。所以指令記憶體的請求必須提早一級送出——在 P 級用 PC mux 選好下一個位址就直接送出去，F 級才收到回應。

x 到底是什麼？

am_x、alu_x、dmm_x 這類值展開後是 2'bx、4'bx——不在乎 (don't care)。合成器可以自由選任何值來省邏輯；模擬時那條線會是 x。

安全的時機：這個欄位的「消費者」被關掉了。例如 bne 那列寫 wm_x，因為 rf_wen = n，writeback mux 的輸出根本沒人要；em_x 之於 lw 也一樣，因為 wb_mux_sel = wm_mem，沒人看 execute mux 的輸出。

危險的時機：消費者其實還活著。如果你替 sw 寫 am_x，位址就算不出來；替 lb 寫 dmm_x，寫回的值會是 x，測試會爆但波形上只看到一片紅色的 x，很難查。拿不準就填一個真的值——多花不了幾個閘。

常見錯誤

x 一旦流進 rf_wen、dmemreq_val 這種致能訊號就是災難：if (x) 在模擬裡不成立、在合成後可能成立。致能欄位永遠寫 y 或 n，不要寫 x。

這兩列只差第五欄。lui（load upper immediate）要的是「把 U 型立即值原封不動寫進 rd」——於是 am_0 + bm_imm_u + alu_add，也就是 0 + imm_u，又一次拿 ALU 當搬運工。auipc（add upper immediate to PC）只是把那個 0 換成 am_pc，變成 pc_Dhl + imm_u。兩道都 rs1_en = n、rs2_en = n：它們根本不讀暫存器。

第 7 章 · 一條指令的旅程

ALU 與分支條件

alu_fn 那一欄只有 11 個合法值，但它背後是整顆 riscv_CoreDpathAlu。這一章拆開它，順便回答兩個每年都有人踩的問題：為什麼移位指令的兩個運算元是反的，以及為什麼 blt 不能只看減法結果的最高位元。

ALU 其實是「解碼器 + 四個單元 + 一顆輸出 mux」

alu_lt 與 slt 是兩件事

alu_lt 讓 ALU 輸出 0 或 1，這正是 slt 指令要寫回暫存器的值。但分支用的 branch_cond_lt_Xhl 是另一套邏輯，它吃的是 alu_sub 的結果（見本章最後一節）。同一個「小於」，兩條不同的路。

assign branch_cond_geu_Xhl   = diffSigns_Xhl ? op0_mux_out_Xhl[31] : ~alu_out_Xhl[31];

為什麼不能只看 alu_out[31]？

直覺的做法是：想知道 a < b，就算 a - b，看結果是不是負的。問題是 32 位元減法會溢位。

所以每種分支該配哪個 alu_fn？

把上面兩張圖合起來想，你自己就能推出來。三個線索：

  • branch_cond_eq_Xhl 只問「alu_out 是不是 0」——任何讓「兩數相同 ⇔ 結果為 0」的運算都可以。已實作的 bne 選了 alu_xor（相同則每個位元都抵銷成 0）。
  • lt / ltu / ge / geu 讀的是 alu_out[31]，而且推理建立在「alu_out = op0 - op1」這個前提上。已實作的 blt 選了 alu_sub。
  • 四顆 mux 的選擇線是 diffSigns_Xhl，它直接看 op0_mux_out_Xhl[31] 和 op1_mux_out_Xhl[31]，和 alu_fn 無關——所以兩個運算元一定要走 am_rdat / bm_rdat，不能拿去放別的東西。
想一想

beq 可以直接沿用 bne 的 alu_xor 嗎？alu_sub 行不行？

看答案

兩個都行。beq 只用到 branch_cond_eq_Xhl，而它只問 alu_out == 0：a ^ b == 0 和 a - b == 0 都恰好等價於 a == b。差別在 br_sel 要填 br_beq，而且控制器裡要多一條 beq_taken_Xhl（第 8 章）。習慣上會讓同一族的指令用同一個 alu_fn，比較好讀。

想一想

bge、bltu、bgeu 三道，alu_fn 該填什麼？為什麼不能填 alu_ltu？

看答案

都填 alu_sub。因為 branch_cond_ge/ltu/geu_Xhl 全都讀 alu_out[31]，而那段推理只有在 alu_out 是「op0 減 op1」時才成立。alu_ltu 會讓 ALU 輸出 0 或 1，alu_out[31] 永遠是 0，六條分支條件線全部失效。要小心的是：ALU 的 alu_ltu 是給 sltu 指令用的，不是給分支用的。

各類指令的提示

以下每一類給的是要問自己的問題，不是答案。照第 6 章五張圖的路徑走一遍，答案自己會浮出來。

暫存器－立即值的邏輯／比較（andi、xori、slti、sltiu）

範本是 ori（第 419 行）。只有 alu fn 那一欄要換。slti／sltiu 的結果是 0 或 1，走的還是 wm_alu——ALU 的 alu_lt／alu_ltu 已經幫你包好了，不要跟分支條件那一套搞混（第 7 章）。

移位（slli、srli、srai / sll、srl、sra）

立即值版的 op1 不是 bm_imm_i，因為移位量藏在指令的 shamt 欄位，datapath 有專門的 shamt_Dhl = {27'b0, inst_shamt_Dhl}（CoreDpath 第 201 行）和對應的 bm_shamt。暫存器版用 bm_rdat，記得 rs2_en = y。至於「誰被移、誰是移位量」——回去看第 7 章那張交叉接線圖。

暫存器－暫存器運算（sub、and、or、xor、slt、sltu、sll、srl、sra）

範本是 add（第 428 行）。op1 改 bm_rdat、rs2_en 改 y、alu fn 換掉，其他照抄。這一族最容易漏的是 rs2_en。

subword load / store（lb、lbu、lh、lhu、sb、sh）

Load 照 lh 的作法：ml_* 和 dmm_* 成對改。Store 只有 ml_* 要改——store 沒有回應要處理，所以 dmm 和 wm 兩欄填什麼都行（rf_wen = n，沒人看 writeback mux）。既有的 sw 那一列就寫了 dmm_w, wm_mem，其實填 dmm_x, wm_x 也一樣跑得動。另外別忘了 store 用的是 S 型立即值 bm_imm_s，不是 bm_imm_i。

常見錯誤

一、列被折行。casez 的一列如果跨行，Verilog 語法上還是合法，但講義明確要求寫在同一行；更實際的理由是：折行之後欄位對不齊，你再也看不出自己少填了一欄。

二、忘了 rs2_en（或 rs1_en）。這兩欄不影響資料路徑，所以測試在 riscvstall 上可能還是會過——然後你到 Objective 3 加 bypass 時炸掉，而且很難聯想到是幾天前填錯的一欄。填表時把它當成「我有沒有真的讀這個暫存器」老實回答。

三、忘了把 .vmh 加進 build/Makefile 的 tests 變數。make check-asm-riscvstall 不會抱怨，它只是沒跑你的新測試，你會以為自己通過了。

四、store 用錯立即值型別。S 型（bm_imm_s）和 I 型（bm_imm_i）的位元擺法不同（第 2 章），填錯的話小的偏移量可能還對、大的就錯，最難查。分支同理：branch_targ_Dhl 用的是 imm_sb，而分支那一列的 op1 要的是 bm_rdat——兩個立即值不要弄混。

想一想

sb（store byte）那一列，memresp muxsel 該填什麼？

看答案

填什麼都可以，dmm_x 最誠實。Store 不寫回暫存器（rf_wen = n），dmemresp_mux_out_Mhl 只會流進 writeback mux，而那顆 mux 的輸出沒有人取用。重點是 mem len 要填 ml_b，mem rq 要填 st，op1 要填 bm_imm_s。

想一想

lui 用 am_0 + bm_imm_u + alu_add。如果你改成 am_rdat + bm_imm_u，測試會過嗎？

看答案

不會，而且會錯得很有趣。lui 的指令編碼裡沒有 rs1 欄位，那五個位元是立即值的一部分，會被當成某個隨機暫存器號碼讀出來加上去。更糟的是 rs1_en 如果也跟著填 y，冒險偵測會對一個根本不存在的相依性 stall，效能莫名其妙變差。這就是為什麼 lui／auipc 的 rs1_en 是 n。

想一想

你加了 bge，控制表那一列 br_sel 填 br_bge、alu fn 填 alu_sub，其他照抄 blt。跑 riscv-bge 測試，結果是「分支永遠不成立」。哪裡漏了？

看答案

漏了控制器裡的 bge_taken_Xhl。any_br_taken_Xhl 目前只 OR 了 bne_taken_Xhl 和 blt_taken_Xhl（第 662–664 行），br_sel_Xhl == br_bge 沒有人去比對，branch_cond_ge_Xhl 也沒有人去讀。要新增 wire bge_taken_Xhl = ( ( br_sel_Xhl == br_bge ) && branch_cond_ge_Xhl ); 並加進那個 OR。

想一想

為什麼 lw 那一列可以填 em_x，addi 那一列卻一定要填 em_alu？

看答案

因為 em 控制的是 execute mux，而它的輸出只有在 wb_mux_sel = wm_alu 時才會被取用。lw 填 wm_mem，writeback mux 選的是記憶體那一邊，execute mux 輸出 x 也沒人理；addi 填 wm_alu，那條路是活的，em_x 會讓寫回暫存器的值變成 x。這就是第 5 章說的「消費者有沒有被關掉」。
