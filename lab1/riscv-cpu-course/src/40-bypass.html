第 14 章 · Bypassing

Bypass：結果早就算好了

第 11 章看到的 stall_hazard_Dhl 解法很粗暴：只要 D 要讀的暫存器還握在 X／M／W 任何一級手上，就把 D 卡住，一路等到寫回 regfile 為止。但把時空圖攤開來看，會發現這個等待幾乎全是白等的——值早就算出來了，只是還沒走到 regfile 而已。

這顆 CPU 的 bypass 接在 D，不是 X

課本上的五級管線通常把前饋接到 X（ALU 的輸入端）。lab1 不是——它的 operand mux 在 D，選好的值才被打進 op0_mux_out_Xhl / op1_mux_out_Xhl：

riscvstall/riscvstall-CoreDpath.v · 第 207–230、246–248 行
  // Operand 0 mux
  wire [31:0] op0_mux_out_Dhl
    = ( op0_mux_sel_Dhl == 2'd0 ) ? rf_rdata0_Dhl
    : ( op0_mux_sel_Dhl == 2'd1 ) ? pc_Dhl
    : ( op0_mux_sel_Dhl == 2'd2 ) ? pc_plus4_Dhl
    : ( op0_mux_sel_Dhl == 2'd3 ) ? const0
    :                               32'bx;
  ...
  // wdata with bypassing
  wire [31:0] wdata_Dhl = rf_rdata1_Dhl;
  ...
      op0_mux_out_Xhl <= op0_mux_out_Dhl;
      op1_mux_out_Xhl <= op1_mux_out_Dhl;
      wdata_Xhl       <= wdata_Dhl;

控制端的 localparam 註解也已經先幫你寫好答案了：

riscvstall/riscvstall-CoreCtrl.v · 第 281、289 行
  localparam am_rdat  = 2'd0; // Use output of bypass mux for rs1
  localparam bm_rdat   = 3'd0; // Use output of bypass mux for rs2

「am_rdat 用的是 bypass mux 的輸出」——目前它接的是 rf_rdata0_Dhl，但命名早就預告了：你要在 regfile 和 operand mux 之間塞一顆新的 mux。

接在 D 的代價

因為 operand 在 D 就選定了，「可以前饋」的條件變成：生產者在 X／M／W 的那個週期，消費者必須正好在 D。課本把 mux 放 X，消費者在 X 時生產者在 M／W，可用的視窗往後移一格。兩種做法都對，但條件寫法不同——不要照抄課本的 EX/MEM、MEM/WB 比較式。

三條線分別從哪裡接出來

每一級要拉出來的，是那一級「這條指令最後會寫進 regfile 的值」在該級已經成形的版本：

來源級接哪條線為什麼是它
Xexecute_mux_out_XhlCoreDpath 288–291 行：ALU 結果與 muldiv 結果選完之後的值，也就是 X 級能給出的最終結果。
Mwb_mux_out_MhlCoreDpath 340–343 行：execute_mux_out_Mhl 和 dmemresp_mux_out_Mhl 選完之後的值——load 的資料也含在裡面。
Wwb_mux_out_WhlCoreDpath 350–356 行：正要寫進 regfile 的那個值（第 411 行接到 .wdata_p）。

D 級不只有 operand mux 在讀 regfile

很容易漏掉的是：rf_rdata0_Dhl / rf_rdata1_Dhl 在 D 級有三個下游，不是只有 operand mux。如果只把 bypass 接到 operand mux，sw 會存到舊值、jalr 會跳到舊位址。

想一想

wdata_Dhl 上面那行註解寫的是 // wdata with bypassing，但下一行卻是 = rf_rdata1_Dhl;。為什麼 riscvstall 裡這樣寫不會錯？

看答案

因為 riscvstall 用 stall 擋掉了所有 data hazard：D 級能往前走的時候，regfile 讀出來的一定已經是最新值。註解是寫給 riscvbyp 的你看的——它標出了「這裡要換成 bypass mux 輸出」的位置。

新的控制訊號要接三個地方

Bypass mux 的 select 是控制訊號，所以它誕生在 riscvbyp-CoreCtrl.v，使用在 riscvbyp-CoreDpath.v。這兩個模組之間沒有直接連線——中間隔著 riscvbyp-Core.v。少寫任何一處，Verilog 不會報錯，只會給你一條永遠是 z 或預設值的線。

第 15 章 · Bypassing

Bypass 控制邏輯與 load-use

好消息：偵測條件不用重寫。第 11 章那個又臭又長的 stall_hazard_Dhl 已經把「D 要的暫存器正握在哪一級手上」算得清清楚楚，你要做的只是改變反應：以前這些條件 OR 起來去卡住 D，現在它們去挑 mux。

riscvstall/riscvstall-CoreCtrl.v · 第 557–562 行（六項裡的前兩項）
  wire stall_hazard_Dhl   = inst_val_Dhl && (
                            ( rs1_en_Dhl && inst_val_Xhl && rf_wen_Xhl
                              && ( rs1_addr_Dhl == rf_waddr_Xhl )

優先權：近的贏

同一個暫存器可能同時符合兩三個條件。想一段連寫兩次 x1 的程式：

示意範例
addi x1, x0, 1
addi x1, x0, 2
add  x3, x1, x1     # 正確答案是 4，不是 2
示意範例 · 只示範 rs1 的其中一項，rs2 與 M／W 請自行類推
// 「rs1 應該從 X 級前饋」——把原本 stall 條件的一項原封不動搬過來
wire rs1_X_byp_Dhl = inst_val_Dhl && rs1_en_Dhl
                  && inst_val_Xhl && rf_wen_Xhl
                  && ( rs1_addr_Dhl == rf_waddr_Xhl )
                  && ( rf_waddr_Xhl != 5'd0 );

// select 編碼：近的先判斷，天然就是優先權
wire [1:0] rs1_byp_mux_sel_Dhl
  = rs1_X_byp_Dhl ? 2'd1        // execute_mux_out_Xhl
  : rs1_M_byp_Dhl ? 2'd2        // wb_mux_out_Mhl
  : rs1_W_byp_Dhl ? 2'd3        // wb_mux_out_Whl
  :                 2'd0;       // rf_rdata0_Dhl
想一想

rs1_X_byp_Dhl 為什麼要 && rs1_en_Dhl？如果拿掉會怎樣？

看答案

rs1_en_Dhl（控制表的 RS_EN 欄）表示這條指令真的要從 regfile 讀 rs1。lui、auipc、jal 這類指令的 op0 選的是 pc 或 const0（am_pc／am_pc4／am_0），指令欄位 rs1 那幾個 bit 根本不是暫存器編號，但它仍然會湊巧等於某個 rf_waddr。拿掉 rs1_en_Dhl 不會馬上壞（因為 op0 mux 本來就沒選 bypass 那條路），但一旦你把 bypass 輸出接到 jumpreg_targ_Dhl 就會出事——而且這種假相依也會讓你的 load-use stall 誤觸發，白白吃掉 IPC。

Load-use：唯一還得 stall 的情況

Bypass 不是萬靈丹。lw 的資料在 X 級還不存在——X 只負責把位址算出來、把 request 送出去，資料要等到 M 級才會以 dmemresp_msg_data 的形式回來：

後果：lw 的下一條指令如果馬上要用它的結果，就非停一拍不可。停完那一拍，生產者剛好從 X 走到 M，就能前饋了：

做一個 is_load 出來

要寫 load-use 的 stall 條件，你得知道「現在 X 級裡那條指令是不是 load」。控制表裡已經有這個資訊，在 MEM_REQ 欄：

  localparam st = 2'd2; // Store
  ...

  wire [1:0] dmemreq_msg_len_Dhl = cs[`RISCV_INST_MSG_MEM_LEN];
  wire       dmemreq_val_Dhl     = ( cs[`RISCV_INST_MSG_MEM_REQ] != nr );

...

想一想

mul／div 的結果也是「X 級才算完」，而且是慢慢算的。它需要像 load 一樣特別處理嗎？

看答案

不需要額外的 stall。iterative muldiv 在結果還沒好的時候，X 級自己就被 !muldivresp_val 卡住了（見第 10 章的 stall 鏈），所以只要 X 沒有 stall，execute_mux_out_Xhl 上就是有效的結果——它已經通過 execute_mux_sel_Xhl 選到 muldiv 那一邊。X 一 stall，D 也跟著 stall（stall_Dhl 含 stall_Xhl），前饋自然不會在錯的週期發生。Objective 4 換成管線式 muldiv 之後才需要重新思考這件事。

W 級那條線真的需要嗎？

有些教科書的 regfile 有「write-through」：同一個週期寫進去的值，讀出來就是新值。那樣的話 W→D 的前饋就不必要。lab1 的 regfile 沒有：

riscvstall/riscvstall-CoreDpathRegfile.v · 第 24–32 行
  // Combinational read ports
  assign rdata0 = ( raddr0 == 0 ) ? 32'b0 : registers[raddr0];
  assign rdata1 = ( raddr1 == 0 ) ? 32'b0 : registers[raddr1];

  // Write port is active only when wen is asserted
  always @( posedge clk )
  begin
    if ( wen_p && (waddr_p != 5'b0) )
      registers[waddr_p] <= wdata_p;
  end

讀是純組合、直接讀 registers[] 陣列；寫是 <=，要到下一個週期才看得到。所以「生產者在 W、消費者在 D」的同一個週期裡，regfile 讀出來的還是舊值——wb_mux_out_Whl 那條線非有不可。

常見錯誤

忘了 inst_val_* 就前饋 bubble。bubble 是「空的一格」，它的 rf_waddr_Xhl 是上一條指令留下的垃圾。沒有 inst_val_Xhl 把關，你會前饋一個不存在的指令的結果。

忘了 rf_wen_*。sw、branch 這些指令不寫暫存器，rf_waddr 欄位是 rx（don't care），不能拿來比。

忘了 != 5'd0。x0 永遠是 0。如果後面有一條指令「寫 x0」（例如 addi x0, x0, 5，合法但沒效果），你把它的結果前饋出去，讀 x0 就會拿到 5。

op0 用 am_pc 的那幾列不該 bypass。jal、auipc、lui 的 rs1_en 是 n；靠 rs1_en_Dhl 把關就對了。

bypass 加了，但 stall_hazard_Dhl 忘了拿掉。模擬會全部通過（stall 本來就給得出正確答案），但 IPC 一點都沒進步。用 +stats=1 比一下 num_cycles 就會發現。

第 16 章 · Bypassing

用測試巨集驗證 bypass

tests/riscv/riscv-macros.h 裡所有名字帶 _BYP 的巨集，都是為了這個 Objective 存在的。它們的手法一模一樣：在生產者和消費者之間插入 nops_ 個 nop，用這個距離去指定要測哪一條 bypass 路徑。

tests/riscv/riscv-macros.h · 第 120–131 行
#define TEST_IMM_DEST_BYP( nops_, inst_, src0_, imm_, result_ )         \
    li    x2, src0_;                                                    \
    inst_ x4, x2, imm_;                                                 \
    TEST_INSERT_NOPS( nops_ );                                          \
    addi  x7, x4, 0;                                                    \
    TEST_CHECK_EQ( x7, result_ );                                       \

#define TEST_IMM_SRC0_BYP( nops_, inst_, src0_, imm_, result_ )         \
    li    x2, src0_;                                                    \
    TEST_INSERT_NOPS( nops_ );                                          \
    inst_ x4, x2, imm_;                                                 \
    TEST_CHECK_EQ( x4, result_ );                                       \

差別只在測哪一端：DEST_BYP 把 inst_ 當生產者（測它的結果能不能被前饋出去），SRC0_BYP 把 inst_ 當消費者（測它的 rs1 能不能收到前饋值）。

nops 的數字直接對應到哪一條 bypass 路徑

生產者在第 c 個週期進 D，那它 c+1 在 X、c+2 在 M、c+3 在 W。插 N 個 nop 的話，消費者在第 c+N+1 個週期進 D：

tests/riscv/riscv-add.S · 第 45–61 行
        TEST_RR_DEST_BYP( 0, add, 13, 11, 24 )
        TEST_RR_DEST_BYP( 1, add, 14, 11, 25 )
        TEST_RR_DEST_BYP( 2, add, 15, 11, 26 )

        TEST_RR_SRC01_BYP( 0, 0, add, 13, 11, 24 )
        TEST_RR_SRC01_BYP( 0, 1, add, 14, 11, 25 )
        ...
        TEST_RR_SRC10_BYP( 2, 0, add, 15, 11, 26 )

SRC01 與 SRC10 的差別是兩個來源誰先產生——它們用兩個獨立的 nops 參數，把 rs1 和 rs2 兩邊的 bypass mux 分開測，還順便測了「兩條 bypass 同時發生」。

常見錯誤

li x2, src0_ 不一定是一條指令。組譯器看立即值決定：塞得進 12-bit 有號數就是一條 addi，塞不進就是 lui + addi 兩條。la x2, label（TEST_LD_*、TEST_JALR_SRC0_BYP 用的）更是固定展開成 auipc + addi 兩條。所以圖上的「距離」要以真正寫入目標暫存器的那一條為準——對 DEST_BYP 沒影響（生產者就是 inst_ 本身），但對 SRC0_BYP 系列，nops_ = 0 時生產者到消費者之間可能還隔著另一個 li 展開的指令。想確認就 +vcd=1 拉波形看。

Branch 與 jalr 的 bypass 要另外測

這兩類指令的消費點不是 ALU operand，所以特別容易漏：

tests/riscv/riscv-macros.h · 第 236–246、271–277 行
#define TEST_BR2_SRC01_BYP( src0_nops_, src1_nops_,                     \
                            inst_, src0_, src1_ )                       \
    li    x2, src0_;                                                    \
    TEST_INSERT_NOPS( src0_nops_ );                                     \
    li    x3, src1_;                                                    \
    TEST_INSERT_NOPS( src1_nops_ );                                     \
    inst_ x2, x3, 1f;                                                   \
    li    x4, 1;                                                        \
    bne   x0, x4, 2f;                                                   \
1:  TEST_CHECK_FAIL;                                                    \
2:                                                                      \

#define TEST_JALR_SRC0_BYP( nops_, inst_ )                              \
    la x2, 1f;                                                          \
    TEST_INSERT_NOPS( nops_ );                                          \
    inst_ x3, x2;                                                       \
    TEST_CHECK_FAIL;                                                    \
1:                                                                      \

TEST_BR2_* 測的是「前饋值有沒有正確地經過 op0／op1 mux 進到 X 級的比較邏輯」；TEST_JALR_SRC0_BYP 測的正是第 14 章提過那條最常被漏掉的路徑——jumpreg_targ_Dhl。它如果讀到舊值，就會跳到不存在的位址，測試直接掛掉而不是回報行號。

Load 的 bypass：TEST_LD_DEST_BYP(0, …) 就是 load-use

測試過了不代表 bypass 有做

這是這個 Objective 最陰險的地方：riscvstall 也會通過全部的 _BYP 測試。stall 給出的答案是正確的，只是慢。所以「make check-asm-riscvbyp 全綠」完全不能證明你的 bypass 在動——它只能證明你沒有把東西弄壞。

要證明 bypass 有效，唯一的辦法是比週期數：

shell
cd $LAB1_ROOT/build
./riscvstall-sim +exe=../tests/build/vmh/riscv-add.vmh +stats=1
./riscvbyp-sim   +exe=../tests/build/vmh/riscv-add.vmh +stats=1

riscvstall 跑 riscv-add 的參考數字是 num_cycles = 468、num_inst = 232、ipc = 0.4957。加上 bypass 之後 num_inst 應該完全一樣（跑的是同一支程式），而 num_cycles 必須明顯下降、ipc 明顯上升。如果兩邊一模一樣，代表：

  • bypass mux 接了，但 select 永遠是 0（控制訊號忘了接，或忘了在 Core.v 拉線）；或
  • stall_hazard_Dhl 還在，hazard 早就被 stall 擋掉，bypass 根本沒機會發生。
